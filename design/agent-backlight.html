Can you tell them apart?

The checks read the settings above and use rules of thumb for a first pass. The glance test gives the better answer, and the real keyboard has the final say.

    Glance test

    10 rounds · 2.5 s each

    The keyboard plays a random state for 2.5 seconds with every label hidden, then goes dark. Name what you saw. It uses your current settings and room light.

      Menu bar icon

      A keycap whose legend says the state. It moves with the keyboard, same rhythm and same flashes, so a look at the screen tells you what the keys tell you. Each state has its own shape, so with Reduce Motion on it still reads as a still frame. It's a template image: a single ink that macOS turns black or white to suit the menu bar.

      What the app does

      1. On start: save your level and auto-brightness setting. brightnessForKeyboard: isAutoBrightnessEnabledForKeyboard:
      2. When a signal starts: switch off auto-brightness and pause idle dimming, so the light stays on while you aren't typing. enableAutoBrightness:forKeyboard: suspendIdleDimming:forKeyboard:
      3. Every frame: set the brightness, about 30 times a second. setBrightness:fadeSpeed:commit:forKeyboard:
      4. Back to Normal: fade to your saved level, then give back auto-brightness and idle dimming.

      Open questions for the hardware test

      • Can an app we build ourselves change the brightness? So far we've only seen that these methods exist.
      • How fast does the LED follow? That sets the real smoothing value.
      • Does commit: NO leave your saved level alone?
